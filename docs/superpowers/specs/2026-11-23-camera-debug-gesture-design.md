# 摄像头识别调试页与手势识别 · 设计

- 日期：2026-11-23
- 状态：待评审
- 涉及项目：Halo（本地信息墙，`E:\workspace_halo\Halo`，分支 `codex/halo`）

## 1. 目的与原因

Halo 已经有一套浏览器端人脸识别：走近时弹出“是 XXX 吗？”，确认后显示个人简报。实际使用中很难判断识别为什么成功或失败——没有分数、没有人脸框、阈值写死在代码里。同时用户希望增加手部手势识别，既能在调试页里看到识别结果，也能真正驱动大屏。

本次要交付两件事：

1. **调试页**：本地打开的摄像头识别调试界面。实时视频叠加人脸框/关键点、每个成员的匹配距离、阈值与差距、帧率；可现场调参、采集样本、导出特征与调参。
2. **手势识别**：基于手部关键点的手势引擎。调试页可视化并记录手势；主屏按已确认的映射执行动作（确认/取消/挥手/点赞），带防误触保护。

当前在 Windows 机器 + USB 摄像头上调试，最终目标是 Mac mini 大屏。设计需同时适配两端。

## 2. 目标 / 非目标 / 反目标

### 目标

- 调试页能回答“这张脸是谁、分数多少、为什么没过阈值”。
- 人脸识别的关键参数（匹配阈值、间距、检测分数、输入尺寸）可在调试页实时调整并持久化。
- 手势可在调试页被看到、记录、调参；同一个引擎在主屏上执行动作。
- 全部计算在浏览器本地完成，不上传视频、特征或关键点。
- 人脸识别算法与默认阈值不变；未调参时识别结果与原行为一致。手势默认开启会改变摄像头启动时机（见 §4），属于已确认的决定。

### 非目标

- 不重新训练人脸或手势模型。
- 不做活体检测、性别年龄/表情识别、多人手势交互语义。
- 不做手势自定义训练；手势判定是规则式，可调判据但手势种类固定。
- 不改动现有简报、订阅、日程、角色播放器功能。
- 本次不重建 Mac 交付包（`MorningBrief-Mac.zip`、`Start-Mac.command` 的依赖检查）；Mac 打包在 Windows 验证稳定后单独做。但源码与新增资源必须保持可打包状态。

### 反目标（即使技术上可行也算失败）

- 路人随意挥手就能切换个人简报或确认身份。
- 手势引擎拖慢或打断现有的人脸识别。
- 调试页在公共大屏上被误打开并暴露视频。
- 引入 CDN 或需要联网才能启动的依赖。

## 3. 约束

- 服务只监听 `127.0.0.1`，所有页面通过 `http://127.0.0.1:4317` 访问；`getUserMedia` 只在本地地址可用。
- 项目原则：所有前端依赖本地托管，不用 CDN。现有做法是把 `node_modules` 中的 face-api 映射为静态路由（`server.mjs:85-93`）。
- 同一页面同时跑 tfjs（face-api）与 MediaPipe，两个运行时共存，内存与 CPU 需可控。
- 人脸特征只存在 `localStorage`，不落盘服务端；本次沿用。
- 现有 Playwright 回归（`test/wall.mjs`）必须继续通过。

## 4. 已确认的决定

| 决定 | 选择 | 原因 |
|---|---|---|
| 手势识别引擎 | MediaPipe Tasks Vision `HandLandmarker` | 远处手部检测明显更稳，21 关键点含手性，CPU 可跑；全本地化可行 |
| 手势判定方式 | 基于关键点几何规则，不用预训练手势分类器 | “挥手”是动态手势，预训练 7 类不含；规则可解释、可在调试页展示判据、可现场调 |
| 调试页形态 | 独立页面 `public/debug.html`，无主界面入口 | 不污染大屏渲染；只能通过 URL 打开，降低误开风险 |
| 手势 → 动作映射 | 见 §5 | 用户已确认 |
| 手势开启后的摄像头 | 常开视频流，人脸识别可暂停 | 挥手需要画面才能唤醒识别；关闭识别只停人脸管线，流和手势保留 |
| `morning.gesture.enabled` 缺省值 | on | 新装大屏即加载手势；首次打开会请求摄像头权限 |
| 跨标签页调参 | 不做实时同步 | 调试页保存后刷新主屏生效；“关闭手势”按事件实时生效 |
| Mac 交付包 | 本次不做 | 先在 Windows 验证，避免处理旧 zip 与 node_modules |

## 5. 手势 → 动作映射（已确认）

| 手势 | 公共屏 / 弹窗 | 个人简报 | 触发条件 |
|---|---|---|---|
| 挥手 wave | 摄像头关闭时开启识别；已开启时无动作 | 返回团队晨报 | 手掌张开，1.2 秒内掌心 x 方向反转 ≥2 次 |
| 张开手掌 openPalm | 「是 XXX 吗？」弹窗中等于“确认” | 无动作 | 仅弹窗打开且 `candidate.via === 'camera'` 时生效；稳定 0.6 秒；2 秒冷却 |
| 握拳 fist | 同一弹窗中等于“取消” | 返回团队晨报 | 同上 |
| 竖大拇指 thumbsUp | 助手点头 + 微笑 | 同左 | 稳定 0.5 秒；2 秒冷却 |

防误触措施：

- 改变状态的确认/取消只在身份确认弹窗的短窗口内生效。
- 所有手势要求连续多帧稳定判定（见 §7.3）。
- 全局开关 `morning.gesture.enabled`，默认 on，可在调试页关闭；关闭后引擎仍运行但不发动作事件。
- 同一时刻只取置信度最高的一只手做动作判定；双手只用于调试展示。
- 挥手抑制“张开手掌”：挥手窗口内及结束后 0.5 秒不产生 `openPalm` 事件；“张开手掌”另要求保持窗口内掌心水平漂移小于阈值（默认 12% 画面宽度）。
- 摄像头生命周期：手势开启时视频流常开，“关闭人脸识别”只暂停 face 管线；只有手势也关闭时才真正断开视频流。

访问：`http://127.0.0.1:4317/debug.html`（不在主界面放入口；README 开发章节注明）。

### 6.2 功能清单

- 设备选择：`enumerateDevices()` 列出 `videoinput`，选择写入 `morning.camera.device`，主屏启动时优先使用。
- 分辨率选择：640×480 / 1280×720 / 1920×1080（ideal，实际以浏览器为准），写入 `morning.camera.size`。
- 叠加层：人脸矩形、68 点关键点、双手 21 点骨架与手性标签。
- 分数面板：对每个已录入成员显示平均距离，第一名高亮，显示阈值与一二名差距；未命中时说明原因（超阈值/差距不足）。
- 参数调节：四个阈值滑杆，实时生效并写入 `localStorage['morning.face.tuning']`；一键恢复默认。
- 人脸样本：为当前选中的成员采集一组描述子（沿用 3 组上限与 `addSample` 的距离约束），可导出/导入整个 `morning.wall.face-templates.v1` 为 JSON 文件。
- 手势面板：当前手势、置信度、连续稳定帧数；最近 20 条手势事件；可导出当前关键点帧作为测试夹具（截取一次检测的 21 点坐标 + 手性 + 时间戳）。
- 性能：显示 face 每帧耗时、hand 每帧耗时、实际检测频率。
- 全局手势开关：`morning.gesture.enabled`（默认 on）。
- 生效提示：页面顶部固定显示“调参保存后请刷新主屏”；切换设备或分辨率后在调试页重新开始视频。
- 拔出摄像头、模型 404、wasm 不支持时显示明确错误。

### 6.3 调试页不做

- 不做识别算法本身的在线学习或自动标定（只提供调参与样本管理）。
- 不在调试页里执行大屏动作；动作只在主界面由 `app.js` 执行。

## 7. 架构

### 7.1 数据流

```
<video> ──┬─ Camera(facade.js) ──> face-api 检测/描述子 ──> 分数排行 ──> onFrame(payload)
          │                                                          ├─ app.js 状态机（识别/弹窗）
          │                                                          └─ debug.js 面板与叠加层
          └─ GestureEngine ──> MediaPipe HandLandmarker ──> classify() ──> 稳定/保持/冷却
                                                                        ├─ debug.js 手势面板
                                                                        └─ app.js 动作分发（带守卫）
```

两个引擎共用同一个 `<video>` 和同一条 `MediaStream`。视频流由 `Camera` 统一持有：手势开启时，关闭人脸识别只停止 face 检测循环，不断开流；只有当手势也关闭（`morning.gesture.enabled` 为 off 且页面已刷新）时，关闭摄像头才真正停止所有轨道。

### 7.3 手势引擎

公共 API：

```js
export class GestureEngine {
  constructor(video, { onResult, onEvent, settings });
  async start();   // 加载模型、启动检测循环
  stop();
  updateSettings(partial); // 调试页实时调参
}
```

- 加载：`FilesetResolver.forVisionTasks('/mediapipe/wasm')`；`HandLandmarker.createFromOptions({ baseOptions:{ modelAssetPath:'/models/hand_landmarker.task' }, runningMode:'VIDEO', numHands:2, ... })`。
- 循环：每 80ms（≈12.5 fps）调用 `detectForVideo(video, performance.now())`，时间戳单调递增。
- 分类器输入：21 个归一化关键点 + 手性。判据：
  - 手指伸展：指尖到腕的距离 / 对应 PIP 到腕的距离 > 阈值，且手指关节近似共线；拇指用夹角与虎口距离。
  - `openPalm`：≥4 指伸展且拇指伸展。
  - `fist`：≤1 指伸展。
  - `thumbsUp`：仅拇指伸展，拇指尖明显高于腕部，手掌呈竖直方向。
  - `wave`：`openPalm` 成立时记录掌心 x，1.2 秒窗口内方向反转 ≥2 次。
- 稳定性：状态机要求同类结果连续 N 帧（默认 4 帧，可由 settings 调）；`openPalm`/`fist` 需满足保持时长（默认 0.6s），`thumbsUp` 默认 0.5s；触发后进入冷却（默认 2s）。
- 优先级：挥手判定优先于 `openPalm`。挥手窗口内及结束后 0.5 秒内不发出 `openPalm`；`openPalm` 额外要求保持窗口内掌心水平漂移小于阈值（默认 12% 画面宽度）。该规则必须有独立的安全回归测试。
- 置信度：以 MediaPipe 的检测/跟踪分数与规则满足度加权，输出 0–1；调试页显示。
- 事件契约：

```js
{ type:'wave' | 'openPalm' | 'fist' | 'thumbsUp', confidence, at, hand:'Left'|'Right' }
```

- 降级：模型或 wasm 加载失败时 `start()` 抛出明确错误；`app.js` 捕获后禁用动作并只在控制台记录，不影响识别。

### 7.4 主界面动作分发（守卫）

```
dialog === 'confirm' && candidate.via === 'camera'
  openPalm -> 触发“是我，打开简报”（同确认按钮）
  fist     -> closeDialog()
personal?.via === 'camera' || personal?.via === 'manual'
  wave/fist -> home()
public 且无弹窗
  wave -> 人脸识别已暂停则恢复；已在运行则无动作
任意
  thumbsUp -> 助手点头 + 微笑（仅角色就绪时）
```

- 所有动作前检查 `morning.gesture.enabled`。
- 动作与现有按钮点击共用同一函数，避免两套逻辑分叉。
- 手势事件在弹窗/页面切换的 300ms 内丢弃，防止状态切换瞬间误触发。
- 默认开启（缺省 on）：主界面加载后惰性加载手势引擎；手势开启时若视频流未启动，则自动启动流（首次安装会请求摄像头权限）。权限被拒绝时手势与人脸都不可用，界面给出明确提示，不反复弹权限框。
- 按钮语义：手势开启时，“关闭摄像头”按钮改为“暂停人脸识别 / 开始人脸识别”，只控制 face 管线；手势与人脸都关闭时才真正断开流，按钮恢复“关闭摄像头 / 开启摄像头识别”。
- 状态文案：`cameraStatus()` 区分“摄像头已开启 · 手势运行中”“人脸识别已暂停”等状态。

### 7.5 摄像头与调参

- `Camera.start()` 读取：`morning.camera.device`（deviceId，缺省 `facingMode:'user'`）、`morning.camera.size`（默认 `1280×720` ideal，回退 640×480）。
- 调参存储（调试页写入，主界面读取）：

```js
morning.face.tuning  = { inputSize:320, detectScore:0.55, matchThreshold:0.48, margin:0.07 }
morning.gesture.tuning = { minConfidence:0.6, stableFrames:4, holdMs:600, cooldownMs:2000, intervalMs:80 }
```

- 默认值必须与当前硬编码值完全一致，未调参时行为不变。
- 生效时机：不做跨标签页实时同步。调试页保存后，主屏在下次加载页面时读取 face/gesture 调参；设备与分辨率改变需要重新启动视频流。调试页顶部固定提示“修改后请刷新主屏”。全局开关的“关闭”在每次事件分发时检查，实时生效；重新开启需要刷新主屏以重新加载引擎。
- `Camera` 帧回调扩展字段（向后兼容）：

```js
{ count, face, match,
  detections:[{ box:{x,y,width,height}, landmarks:[{x,y}] }],
  scores:[{ id, score }], threshold, margin, timings:{ detectMs } }
```

调试数据始终计算（成员数很少，开销可忽略），绘制只在调试页发生。

### 7.6 资源与静态托管

- `@mediapipe/tasks-vision` 锁定精确版本（实施时确认 API，当前 npm 最新为 1.2.3）。
- `server.mjs` 静态映射：
  - `/mediapipe/vision_bundle.mjs` → `node_modules/@mediapipe/tasks-vision/vision_bundle.mjs`
  - `/mediapipe/wasm/*` → 包内 `wasm/` 下实际存在的 `.js` / `.wasm`（SIMD 与 nosimd 两套，按目录列举注册）
  - `/models/hand_landmarker.task` → `public/models/hand_landmarker.task`
- MIME：`.wasm: application/wasm`、`.mjs: text/javascript; charset=utf-8`、`.task: application/octet-stream`。
- 模型文件约 8 MB，随仓库提交；README 与 `public/models/NOTICE`（新增）注明来源 URL 与 Apache-2.0 许可。

### 7.7 隐私

- 视频帧、关键点、描述子均不离开浏览器。
- 调试页不录制、不截图、不上传；导出的 JSON 仅由用户手动保存。
- 特征与调参与现有一样存 `localStorage`，清除浏览器数据即删除。

## 8. 测试策略

- **单测（`node --test`）**：
  - 分类器：用构造的关键点数组验证 `openPalm`、`fist`、`thumbsUp` 判定与边界（半弯曲手指、侧向手掌）。
  - 挥手：构造掌心 x 序列验证窗口内反转计数与冷却。
  - 状态机：稳定性、保持时长、冷却、开关关闭时不发动作事件。
  - `rank()` 与带调参的 `identify()`：阈值/间距边界。
- **浏览器回归（Playwright，沿用假摄像头）**：
  - 现有全部用例通过；每个用例在页面加载前用 `addInitScript` 固定 `morning.camera` 与 `morning.gesture.enabled`，避免默认开启改变既有流程。
  - 新增：手势默认开启时页面自动启动流与手势引擎；权限拒绝时给出提示且不崩溃。
  - 新增：手势开启时点击“暂停人脸识别”，视频轨道保持 `live`、手势引擎继续；手势关闭后关闭摄像头，轨道才停止。
  - 调试页加载：视频挂载、面板渲染、无手部时显示“未检测到”。
  - 模型 404 时主界面手势禁用且人脸识别不受影响。
- **手测清单**（Windows 现在 / Mac 之后各跑一遍）：
  - 2 米内张开手掌/握拳/点赞/挥手，观察调试页关键点与置信度。
  - 调匹配阈值后识别行为符合预期，刷新后保持。
  - 大屏上确认弹窗可被手势确认/取消；个人简报挥手返回。
  - 路人经过不触发状态切换（至少 10 次经过测试）。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 远处手部太小，关键点抖动 | 默认 1280×720；调试页可切分辨率；稳定帧 + 保持时长；置信度阈值可调 |
| 与 tfjs 并发导致掉帧 | 手部循环 12 fps 起步，调试页显示两套耗时；可在设置里降频 |
| 误触发切屏 | 动作限定在弹窗/个人屏上下文；全局开关；冷却；切换后 300ms 丢弃 |
| MediaPipe 版本 API 变化 | 锁定精确版本，实施时先跑通最小示例再集成 |
| 模型/wasm 加载失败 | 明确错误提示；手势禁用；人脸识别不受影响 |
| 默认开启导致首次打开就请求摄像头权限、加载模型 | README 与首屏状态说明；权限拒绝时进入手动模式且不反复弹框；开关一键关闭 |
| 关闭识别后摄像头指示灯仍亮，用户误以为已关闭 | 状态文案明确写“手势运行中，摄像头保持开启”；README 说明隐私影响 |
| 公共大屏隐私 | 调试页只有 URL 入口；不录制；README 提示在公共场合使用注意 |

## 10. 实施顺序（供计划阶段参考）

1. 调试页地基：Camera 调试数据、设备/分辨率、分数面板与叠加层、调参持久化。
2. 手势引擎：MediaPipe 集成、分类器、状态机、单测；调试页可视化与手势日志。
3. 主屏集成：事件分发与守卫、全局开关、降级路径。
4. 回归与文档：现有测试、浏览器冒烟、README。

## 11. 留给实施者的决定

- MediaPipe 具体版本与文件清单以安装后实际包结构为准；若 1.x API 与设计不一致，以官方文档为准并在实现说明中记录。
- 分类器判据的具体数值（如伸展比例、虎口夹角）先用合理初值，再由调试页实测调整；只要求默认值能通过单测夹具。
- 测试夹具的生成方式：优先用调试页“导出当前关键点”捕获真实帧，再清理为只含分类所需字段。
- 叠加层绘制用 canvas 2D（与现有角色 canvas 独立），不引入绘图库。
